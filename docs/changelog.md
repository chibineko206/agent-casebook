# 変更履歴と開発の判断

この仕組み（agent-casebook）自体の開発記録。テンプレートから作った利用者のリポジトリには、利用者の案件を `cases/` に置くので、開発記録はここに置く。
旧来は `cases/casebook-ops/CASE.md` に時系列で書いていた。テンプレート配布への変更（2026-11-26）で、判断と未決だけをここへ要約して移した。詳細な経緯はこのリポの git 履歴（`cases/casebook-ops/CASE.md` の最終版）にある。

書き方: 新しい順に、日付・題材・やったこと・判断を書く。未決事項は末尾の「未決事項」節に 1 か所で持つ。

## 2026-11-26 配布をテンプレートリポジトリ方式に変更

- clone して `origin` を外す案内をやめ、GitHub の Template repository にした。利用者は「Use this template」で自分の非公開リポジトリを作る
- 判断: テンプレートから作ったリポジトリは配布元と履歴がつながらないので、`origin` の外し忘れで個人の記録が公開側へ push される問題が構造上なくなる
- 判断: 配布するのは仕組みだけ。`cases/` は空（`.gitkeep`）、`INDEX.md` は案件の行が無い表にして渡す。この仕組みの開発記録は `docs/changelog.md`（このファイル）に置く
- 判断: 仕組みの更新は `tools/update-from-upstream.py` で取り込む。履歴がつながらないので `git pull` は使えない。取り込み対象は仕組みのファイルに限り、利用側の固有ファイル（`cases/`、`private/`、`INDEX.md`、`.claude/rules/`、`*.local.sh`）には触れない
- 判断: 取り込み対象は仕組みのファイルに、保守文書が従来から対象にしていた `templates/`、`docs/manual.html`、`docs/chat-writeback-prompt.md` を足した。ディレクトリ単位の対象は配布元に揃え、利用側が足したファイルは消す（`*.local.sh` は残す）。自動コミットはしない
- 判断: 改修中の記録は `cases/dev-<題材>/` に書いてよいが、PR の最後のコミットで外し、判断と未決をこのファイルへ要約する（`docs/001-maintenance.md` 1 章）
- 判断: `docs/001-maintenance.md` を「利用側がコピー用スクリプトで取り込む」前提から、テンプレート配布と取り込みスクリプトの前提に書き換えた

## 2026-10-19 /doc-check を点検から修正までの既定に変更

- 既定で書き方の修正まで適用し、報告だけで止める動作は `--report-only` で残した
- 判断: 毎回「全部直して」と答えていた確認の往復をなくす。事実の誤りは直さず「要確認」に回す

## 2026-10-16 push 先の確定と Launcher の検証

- 判断: Launcher の app と `casebook://` はマシンに 1 つしか持てず、`launch.py` のあるリポの案件しか解決できない。このリポでビルドすると、日々使うリポのダッシュボードのボタンが動かなくなる
- 判断: このリポでの Launcher の検証は `launch.py --dry-run` を当面の手段とする

## 2026-10-15 切り出しと移行措置の完了

- 非公開の作業リポから仕組みを切り出して初版を作成した。`CLAUDE.md` の軽量化、`/done` のスクリプト化（`tools/casebook.py`）、生成し直せるものを追跡しない規則、`.claude/rules/` と hook のローカル拡張点を入れた
- `/writeback` を `casebook.py` 経由に作り直し、マニュアルから利用側固有の節を外した
- 判断: `CLAUDE.md` は取り込み対象、マニュアルは仕組みの解説だけを持つ。利用側の固有規則は `.claude/rules/` に置く
