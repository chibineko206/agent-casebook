文書 `$ARGUMENTS` を『理科系の作文技術』（木下是雄）の要点に沿って点検し、結果を報告する。
判定の後に修正まで行うかは、起動のされ方で決まる。

| 起動 | 判定の後にすること |
|---|---|
| **明示**: ユーザーが `/doc-check` と打った | 文書を書き換えず、判定と書き直し案を報告して「修正するか」を聞く |
| **自動**: `CLAUDE.md` の仕上げ規則や `/done` の手順 2 に従い、Claude がこの手順を読んで実行した | 書き方の要修正を Edit で書き直し、修正前後を報告する。聞くのは「要確認」だけ |

明示の報告の後にユーザーが「直して」と言えば、自動と同じ手順 3 で書き直す。

引数が空の場合は、このセッションで作成・更新した文書（Markdown / HTML）を候補として挙げ、
ユーザーに確認してから進める。

## 1. 文書を読む

- 対象は Markdown と HTML。HTML は本文テキストだけを見る（スタイルとスクリプトは対象外）
- 文書の記述から、読み手と主題をそれぞれ一文で言い直す。言い直せなければ観点 1 を「要修正」にする
- 引用や参考資料など、他人が書いた部分は判定対象外。書き換えもしない

## 2. 観点ごとに判定する

| # | 観点 | 確認すること |
|---|---|---|
| 1 | 心得 | 読み手が決まっているか。文書全体の主題が 1 つに絞れているか。主題が一文（目標規定文）で言えるか。必要なことは漏れなく、不要なことは一切書いていないか |
| 2 | 組み立て | 結論が冒頭にあるか。リード文だけで趣旨が分かるか。全体像（概観）を示してから細部・個別データに入る順序か。どこで読み止めても要点が伝わるか |
| 3 | 構成 | 一段落一主題か。段落の冒頭文だけを拾って読んで筋が通るか |
| 4 | 文 | 一文が短いか。主語と述語がねじれていないか。修飾語で脇道に逸れる「逆茂木型」の文が無いか |
| 5 | 事実と意見 | 事実は断定、意見は「〜と考える」と明示されているか。ぼかし言葉（ほぼ・約・ほど・ぐらい・たぶん・ような・らしい・みたいな）が残っていないか。二通りに読める文が無いか |

- ぼかし言葉でも、数値の丸めを示す「約」のように意味を持つ用法は指摘しない。責任を曖昧にする用法だけを指摘する
- 判定は「適合」か「要修正」の二択。迷ったら「要修正」にして理由を書く

## 3. 書き直す（自動のとき、または明示の後にユーザーが修正を指示したとき）

要修正の箇所を Edit で書き直す。全文の上書きはしない。

- 直すのは書き方だけ。段落の分割・統合、文の切り分け、語順、意見の明示（「〜と考える」）、ぼかし言葉の除去、冒頭への結論の移動
- **事実の誤りや、根拠が文書内に無い主張は直さず、「要確認」として報告に回す。**書き手が確認する必要があるため
- 数値、固有名詞、出典、コードは変えない
- 文体は文書の既存の文体に合わせる
- 書き直した結果が元の意味から離れていないか、該当箇所を読み直して確かめる

## 4. 報告する

次の書式で出す。

```markdown
## /doc-check <ファイル>

読み手: <一文>
主題（目標規定文）: <一文>

| # | 観点 | 判定 | 対処 |
|---|---|---|---|
| 1 | 心得 | 適合 / 要修正 | 修正済み / 要確認 / — |
| 2 | 組み立て | 適合 / 要修正 | 修正済み / 要確認 / — |
| 3 | 構成 | 適合 / 要修正 | 修正済み / 要確認 / — |
| 4 | 文 | 適合 / 要修正 | 修正済み / 要確認 / — |
| 5 | 事実と意見 | 適合 / 要修正 | 修正済み / 要確認 / — |

### 修正した箇所

#### <#>. <観点>: <何が問題だったか一言>
- 修正前: 「<引用>」（<見出しや位置>）
- 修正後: 「<書き直した文>」

### 要確認（書き手の判断が要るもの）

#### <#>. <観点>: <何が問題か一言>
- 該当箇所: 「<引用>」（<見出しや位置>）
- 理由: <事実の確認が要る、根拠が無い、など>
- 書き直し案: 「<案>」
```

- 修正にも要確認にも該当箇所を必ず引用する。引用できない指摘はしない
- 指摘は重要なものから並べる。些末な語句の揺れを列挙して埋めず、1 観点あたり多くとも 5 件にする
- 全観点が適合なら、表の下に「修正不要」と 1 行書く
- **明示のとき**は表の「対処」列と「修正した箇所」の節を出さない。要修正をすべて「要修正の詳細」として書き直し案つきで報告し、最後に「修正するか、どの指摘を採るか」をユーザーに確認する
- **自動のとき**は上の書式どおりに出す。要確認が 1 件でもあれば、最後に「要確認の項目をどうするか」をユーザーに確認する。無ければ確認せずに終える
